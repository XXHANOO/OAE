## 6. Implementation Details

### Public contract

The public dataclass is exactly:

```text
DecisionOptionChainSnapshot
    product
    expiration_date
    settlement_style
    source
    decision_ts_utc
    snapshots
```

It is a frozen slots dataclass. `snapshots` is an immutable tuple of the
approved `DecisionOptionSnapshot` objects and no redundant contract tuple is
stored.

The public builder is exactly:

```text
build_decision_option_chain_snapshot(
    contracts,
    quotes,
    decision_ts,
    *,
    product,
    expiration_date,
    source,
)
```

`product` and `source` must each have exact type `str` and be non-empty.
Their values are preserved exactly without stripping, uppercasing, aliasing,
or inference. The output settlement style is always `SettlementStyle.PM`;
there is no settlement-style argument.

### Target filter


The supplied contract universe is authoritative. A canonical SPX contract
with vendor root `SPXW` remains eligible, and reversed or same-day date-only
first/last-seen metadata does not create an invented intraday listing rule.

### Source-scoped identity and quote routing

```text
Contract identity key:                 (source, contract_id)
contract_id alone used for routing:    NO
Cross-source same-ID contamination:    NO
Contract ID generated:                 NO
Vendor/root/strike ownership inference:NO
```

Every quote is routed only by exact `(quote.source, quote.contract_id)`.
Quotes for another source, product/expiration contract, AM contract, unknown
contract ID, or filtered-out contract are irrelevant to the target chain.
Within the eligible target chain, any duplicate exact source-scoped contract
identity raises `DecisionOptionChainSnapshotIntegrityError`, including an
identical duplicate record. Same-strike distinct identities are preserved.

### Approved primitive reuse and state preservation

For each eligible contract, the builder calls:

```text
build_decision_option_snapshot(
    contract,
    exact_source_scoped_contract_quote_stream,
    canonical_decision_ts_utc,
)
```

exactly once. It is never called for filtered contracts.

```text
Per-contract builder reused:           YES
As-of logic reimplemented:             NO
Quote-age logic reimplemented:         NO
Quote-quality logic reimplemented:     NO
MISSING logic reimplemented:           NO
Same-timestamp ambiguity reimplemented:NO
```

All eligible contracts remain represented when their resulting status is:

```text
VALID
MISSING
STALE
CROSSED

ZERO_BID
ZERO_SIZE
```

Quality-first chain filtering is not performed. The latest eligible invalid
quote remains authoritative over an earlier valid quote. Empty/all-future
streams remain MISSING with no selected quote, no age, and no synthetic
quote. Distinct payloads at the maximum eligible timestamp propagate the
authoritative `AsOfSelectionIntegrityError` unchanged; sequence number,
quality, input order, and other fields do not become tie-breaks.

### Determinism, time, and empty chains

Canonical snapshot order is exactly:

```text
contract.strike
then contract.option_type.value
then contract.contract_id
```

Caller contract order is irrelevant. Caller quote order is irrelevant,
subject to the approved exact-payload-equivalent duplicate semantics. Neither
input sequence nor any DTO is mutated.

The supplied decision must represent exactly 13:30:00
`America/New_York`. The implementation canonicalizes through existing
timezone utilities, accepts summer/winter and equivalent non-ET aware
representations, rejects other aware instants with the chain integrity error,
and allows existing naive-timestamp rejection to propagate.

No matching contract returns a valid exact-metadata chain with
`snapshots == ()`; no contract is synthesized and no error is raised merely
because the target chain is empty.
