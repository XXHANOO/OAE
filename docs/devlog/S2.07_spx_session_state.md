## 6. Implementation Details

`IndexSessionRecord` has exactly the nine canonical `core.index_sessions`
fields. It is a frozen `StrictModel`, forbids extras, requires strict boolean
and strict positive `Decimal` state values without rounding or float
conversion, canonicalizes aware timestamps with `to_utc(...)`, validates the
session timestamp order and ET dates, and enforces the high/low and contained
open/decision-price invariants.

`build_spx_session_state(...)` requires an explicit keyword-only
`spx_official_prev_close: Decimal`. It does not derive, select, inspect, or
guess an official close from any bar. It validates a supplied trading session,
uses the existing DST-aware 09:30 and 13:30 temporal primitives, and selects
only exact target-date intervals fully available in the regular-session
decision window. Required bars are addressed by canonical end-timestamp
identity, so caller order is irrelevant and the caller sequence is not
mutated.

The builder requires exactly one VALID bar for each of 240 intervals from
09:30–09:31 through 13:29–13:30. Missing, duplicate, off-grid, or mixed-source
required bars hard fail. Multiple `raw_file_id` values from the same source are
allowed. Other-date, pre-open, 13:30–13:31, and later bars are filtered before
quality, source, or duplicate inspection, so neither their values nor metadata
can influence the returned state or its exceptions.

## 10. Known Limitations / Risks

The frozen mathematics requires the previous trading session OFFICIAL SPX
close.

S2.07 does not define which provider field constitutes that official close.

A provider's final regular-session minute bar may only supply the explicit
`spx_official_prev_close` argument when upstream provider semantics explicitly
guarantee that value is the official SPX close.

Otherwise the upstream pipeline must fail closed.

This is intentionally NOT resolved by silently using a final minute bar.
