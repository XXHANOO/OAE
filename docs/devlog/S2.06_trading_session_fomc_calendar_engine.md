## 6. Implementation Details

`TradingSessionRecord` has exactly the eight canonical fields and validates
strict `session_seq`/boolean inputs, aware UTC-canonicalized timestamps,
same-ET-date timestamps, open-before-close ordering, and supplied session
classification consistency. It does not infer calendar facts.

`MacroEventRecord` has exactly the eight canonical fields, supports only
`FOMC_DECISION` and `FOMC_PRESS_CONFERENCE`, preserves input strings without
normalization, accepts point events, and validates aware UTC-canonicalized
same-ET-date timestamps.

`validate_trading_session_sequence(...)` rejects duplicate session dates and
requires strictly increasing `session_seq` across trading rows ordered by
date; gaps, non-trading rows, and caller input order do not change validity.

`build_session_calendar_gate(...)` derives the decision time through the
existing DST-aware temporal layer. `full_session_eligible` is exactly
`is_trading_day AND is_full_session AND NOT is_half_day`; it deliberately does
not use `xsp_0dte_exists`. The FOMC window is `[13:30, 16:00)` ET,
positive-duration events are `[start, end)`, and points block iff within the
half-open window. Target-date unverified records and any duplicate `event_id`
raise `CalendarIntegrityError`. `SessionCalendarGate` is a frozen slots
dataclass and exposes no decision reason or non-calendar eligibility fields.
