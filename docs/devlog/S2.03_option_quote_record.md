## 6. Implementation Details

`OptionQuoteRecord` inherits the existing strict, frozen `StrictModel` and
declares exactly these fields in canonical `core.option_nbbo` order:
`contract_id`, `quote_ts_utc`, `session_date_et`, `bid_px`, `ask_px`,
`bid_size`, `ask_size`, `bid_exchange`, `ask_exchange`, `quote_condition`,
`sequence_no`, `source`, and `raw_file_id`. Nullable-typed fields remain
required keys because no default was added.

`contract_id`, `source`, and `raw_file_id` are required, non-empty, preserved
exactly, and otherwise opaque. The DTO performs no UUID/OCC parsing,
contract-master lookup, raw-manifest lookup, source mapping, ID generation,
or cross-record validation. Exchange strings and raw vendor condition text
are preserved without trimming, case conversion, interpretation, inference,
or conversion between empty strings and `None`. Provider sequence metadata is
preserved as a nullable integer and is not used to sort, select, or resolve
same-timestamp records.

The existing `oae.temporal.to_utc` utility rejects naive quote timestamps and
converts aware timestamps to equivalent UTC instants while preserving exact
microseconds. `session_date_et` remains explicit caller/provider-mapped data
and is neither derived nor cross-validated. No decision timestamp is embedded
and no freshness or backward-as-of rule is applied.

Prices remain unquantized `Decimal` values and sizes remain the canonical
integer fields. Locked quotes, crossed quotes, zero bids, and zero sizes are
intentionally structurally representable raw observations. The DTO neither
classifies nor repairs them and introduces no `quality_status`, `quote_valid`,
`quote_age`, `quote_age_ms`, `source_quote_id`, or `recv_ts_utc` field.

- This stage provides the raw DTO only; provider adaptation, normalization,
  raw-lineage cross-validation, persistence, quote-quality classification,
  freshness, strict backward-as-of selection, and decision snapshots remain
  deferred.
- Structurally representable locked, crossed, zero-bid, zero-size, old, or
  post-decision observations are not thereby usable for trading. Downstream
  authorized stages must classify and select them under the frozen rules.

  same-timestamp tie-break exists in this stage; later selection must resolve
  or fail closed under its separately authorized contract.
- `contract_id`, `session_date_et`, source metadata, sequence metadata, and
  `raw_file_id` remain caller supplied and are not authenticated, derived, or
  cross-validated by this boundary DTO.
- Decimal physical quantization to the existing `DECIMAL(18,6)` table remains
  a later persistence responsibility; the DTO intentionally preserves input
  Decimal precision.
- IANA tzdb provenance/version pinning remains deferred from Sprint 1; this
  stage correctly reuses the approved timezone-aware temporal utility.
