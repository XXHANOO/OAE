## 6. Implementation Details

The implementation adds one function and returns DuckDB's connection object
directly. It converts only the supplied `str | Path` value to `str`, passes it
explicitly as `database`, and explicitly requests `read_only=False`.

The caller retains lifecycle ownership and must close the returned connection.
There is no wrapper class, implicit cleanup, connection cache, singleton,
pool, database-path constant, directory creation, path expansion or
normalization, runtime setting, extension loading, schema creation, migration
discovery, SQL-file access, or production SQL execution.

The close/reopen test creates `persistence_probe` only inside a pytest
`tmp_path` database. It is test evidence for file-backed persistence and is
not production schema or migration code.
