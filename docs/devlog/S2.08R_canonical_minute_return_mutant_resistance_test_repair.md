- Assigned objective: Repair the S2.08 acceptance suite so it independently
  kills the incorrect later-return formula
  `ln(current_close / current_bar.open)` while preserving the correct frozen
  formula `ln(current_close / previous_bar.close)`.
- Explicit in-scope work: Add one focused regression to
  `tests/unit/test_canonical_minute_returns.py` using an interior bar whose
  current open is deliberately distinct from the preceding canonical close;
  preserve the current close; verify the exact correct denominator; reject

  return tuple unchanged.

  remain present; the new test kills the specified mutant; required local
  verification and exact implementation-SHA CI succeed; production blobs

Root cause of the original rejection: the S2.08 default canonical bar helper
set every later bar's open equal to the previous bar's close. Therefore the
existing later-return formula tests could not distinguish the correct
`ln(current_close / previous_close)` formula from the wrong
`ln(current_close / current_bar.open)` mutant. S2.08 production mathematics
and implementation were correct; this remediation closes only that test gap.

## 6. Implementation Details

One independent regression was added:

```text
test_s208r_later_return_ignores_current_bar_open
```

The test uses the existing valid canonical bar list and targets interior index
`123`, comfortably away from both boundaries. It captures the previous close
and current close, then replaces only the target bar's OPEN, HIGH, and LOW.
Timestamp, session date, CLOSE, source, raw-file identity, and quality remain
unchanged. HIGH and LOW are adjusted only to keep the replacement OHLC values
coherent.

The regression independently asserts the open/previous-close dislocation, the
unchanged current close, the exact correct close-to-close return within

becomes the explicitly rejected wrong value and the tuple-equality assertion
also fails. Therefore the mutant-resistance self-check answer is YES.
