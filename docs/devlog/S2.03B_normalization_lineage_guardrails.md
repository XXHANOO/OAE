## 6. Implementation Details

`normalize_index_bar_1m` and `normalize_option_quote` first require exact
`RawFileManifestRecord` class identity and rematerialize its Python field
values through the canonical Pydantic schema. They then read `adapter.source`
exactly once, require a non-empty `str`, compare it to the revalidated
manifest source using exact string equality, and only then invoke the adapter
with the exact opaque `manifest.raw_file_id` as the required keyword-only
argument.

`normalize_option_contract` snapshots and validates the adapter source, calls
the contract adapter without inventing any manifest or raw-file parameter,
and enforces exact source equality against the canonical contract DTO.

All three paths require exact DTO class identity with `type(...) is ...`.
They dump Python field values and validate those values through the exact
approved Pydantic class, so an already-typed object created with
`model_construct(...)` cannot bypass canonical validators. Pydantic validation
failures are wrapped in `NormalizationIntegrityError` with the original
`ValidationError` as the cause. Valid calls return the newly rematerialized
canonical DTO.

Bar and quote outputs must exactly match both the snapshotted source and the
revalidated manifest raw-file identity. Mismatches fail closed without
mutation, copying with updates, string canonicalization, ID generation, or any
other repair. Exceptions raised by adapter parsing/adaptation itself are not
caught and therefore propagate unchanged.

The boundary deliberately does not inspect quote prices/sizes for quality,
quote timestamps for decision/freshness eligibility, or sequence metadata for
selection. Locked, crossed, zero-bid, zero-size, old, and post-decision raw
quotes remain structurally normalizable when their canonical DTO and lineage
are otherwise valid.
