## 6. Implementation Details

### Public contract

Module `src/oae/data/atm_selection.py` exports exactly:

```text
ATMCallPutPairSelection
ATMCallPutPairSelectionIntegrityError
select_spx_atm_call_put_pair
```

The public dataclass is a frozen slots dataclass with exactly:

```text
strike
call_snapshot
put_snapshot
```

The public selector signature is exactly:

```text
select_spx_atm_call_put_pair(dataset, chain)
```

There is no free-floating spot or strike argument.

### Frozen ATM rule and authority

```text
S_t source:             dataset.session_state.spx_decision_px
Candidate strikes:      all distinct listed strikes in chain.snapshots
ATM rule:               argmin |K - S_t|
Tie-break 1:            smallest absolute distance
Tie-break 2:            lower strike
Arithmetic:             Decimal
Float conversion:       NO
Rounding/quantization:  NO
```

The selector first validates the narrow bundle contract and collects every
listed strike represented by a contract snapshot. It then selects `K_ATM`
with the exact key `(abs(strike - S_t), strike)`. Only after `K_ATM` is fixed
does it partition snapshots at that exact strike by `OptionType.CALL` and
`OptionType.PUT`.

Selection ordering is explicitly:

```text
ATM strike chosen before CALL/PUT completeness: YES
ATM strike chosen before quote validity:         YES
ATM strike chosen before quote quality:          YES
Nearest valid pair selection:                    NO
Nearest complete pair selection:                 NO
Fallback after incomplete selected strike:       NO
```

Production selection does not read `quality_status`, bid, ask, size, quote
age, selected quote, mid price, or raw quote streams. A PUT-only, CALL-only,
or MISSING-only strike is a listed candidate and may be `K_ATM`.

### Pair semantics

```text
call_snapshot: unique CALL snapshot at K_ATM or None if CALL contract absent
put_snapshot:  unique PUT snapshot at K_ATM or None if PUT contract absent
MISSING quote snapshot treated as absent contract: NO
MISSING snapshot preserved:                       YES
Invalid snapshot preserved:                       YES
Exact snapshot object identity preserved:         YES
```

A missing contract side does not cause fallback. A listed contract with a
MISSING, STALE, CROSSED, LOCKED, ZERO_BID, or ZERO_SIZE snapshot remains the
exact returned object when it belongs to the selected strike.

### Selected-side ambiguity policy

The canonical specification defines the lower-strike tie-break for ATM
STRIKE selection. It does not define a provider-neutral tie-break between
multiple distinct CALL contracts or multiple distinct PUT contracts at the
same selected strike. S2.12 therefore fails closed:

```text
Multiple CALLs at selected K_ATM: HARD FAIL
Multiple PUTs at selected K_ATM:  HARD FAIL
Exception: ATMCallPutPairSelectionIntegrityError
contract_id tie-break:            NO
quality tie-break:                NO
input-order tie-break:            NO
nonselected multiplicity:         DOES NOT BLOCK
Frozen mathematics changed:       NO
```

This is an integrity refusal to invent an unauthorized financial tie-break.

### PIT and bundle coherence

```text
Input: PITDecisionSessionDataset + DecisionOptionChainSnapshot
Free-floating spot argument:                         NO
Chain decision timestamp equals dataset timestamp:  REQUIRED
Product:                                             SPX ONLY

Same-day expiry required by selector:                NO
```

Narrow defensive integrity checks cover exact input types, tuple snapshot

Quote age, bid/ask, size, quality, and as-of semantics remain upstream-owned.

## 10. Known Limitations / Risks

1. Expiration eligibility is deliberately caller-owned. The selector accepts
   a separately supplied same-day or future-expiry SPX PM chain but does not
   discover or decide the next eligible expiry.
2. Quote validity remains deliberately upstream/downstream-owned. S2.12
   preserves structural pair state; S2.13 must fail closed when x9 cannot be
   computed from two valid quotes.
3. Multiple distinct CALLs or PUTs at the selected strike hard-fail because
   the canonical specification provides no provider-neutral same-side
   contract tie-break. This preserves integrity but requires upstream chain
   identity quality.
4. Independent Human + ChatGPT audit remains pending. S2.13 is not authorized
   by this report.
