## 6. Implementation Details

`IndexBar1mRecord` inherits the existing strict, frozen `StrictModel` and
declares exactly these fields in canonical order: `symbol`, `session_date_et`,
`bar_start_ts_utc`, `bar_end_ts_utc`, `open`, `high`, `low`, `close`,
`observation_count`, `source`, `raw_file_id`, and `quality_status`.

The symbol validator accepts exactly `SPX` and performs no normalization. The
existing `oae.temporal.to_utc` utility rejects naive timestamps and converts
aware timestamps to canonical UTC instants. A model-level validator requires
the half-open interval start to precede its end and requires exactly 60
seconds of elapsed time; fractional-second endpoints are permitted when that
duration remains exact. `session_date_et` remains explicit caller data and is
not derived or cross-validated against timestamps.

All four prices use `Decimal` and are preserved without quantization, float
conversion, ordering constraints, or quality classification.
`observation_count` is a strict integer at least zero. `source` and
`raw_file_id` must be non-empty and are otherwise preserved, with the latter
treated as an opaque identifier. `quality_status` reuses the canonical
`QualityStatus` enum: every current member is representable, unknown values
are rejected, and the record performs no status derivation. No 13:30 ET or
other decision-time eligibility rule is applied at this DTO boundary.
