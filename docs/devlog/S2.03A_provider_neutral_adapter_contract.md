## 6. Implementation Details

`ProviderAdapter` is a `typing.Protocol` with the read-only conceptual
property `source -> str`. It introduces no base provider class, provider enum,
registry, alias, runtime validation, or canonicalization.

`IndexBar1mAdapter`, `OptionContractAdapter`, and `OptionQuoteAdapter` are
separate capability protocols. Each has its own contravariant raw-record
`TypeVar`, so concrete adapters may bind mappings, SDK objects, tuples, Arrow
rows, custom raw dataclasses, or other provider-native representations without
freezing a universal `dict`, `Mapping`, or `Any` boundary.

Each capability adapts exactly one raw record into the existing approved DTO:

- `adapt_index_bar_1m(..., *, raw_file_id: str) -> IndexBar1mRecord`
- `adapt_option_contract(...) -> OptionContractRecord`
- `adapt_option_quote(..., *, raw_file_id: str) -> OptionQuoteRecord`

The index-bar and option-quote methods require `raw_file_id` as a keyword-only
argument with no default. The option-contract method intentionally has no
`raw_file_id` parameter because its approved DTO contains no such field. The
module defines no concrete implementation, Pydantic model, dataclass, helper,
factory, registry, provider client, batch API, transport API, I/O, persistence,
normalization, selection, or downstream decision parameter.
