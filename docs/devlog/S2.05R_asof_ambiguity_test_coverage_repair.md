## 6. Implementation Details

Original stage: S2.05 — Strict Backward As-Of Selection.

Human + ChatGPT verdict: REJECTED, severity P2. The production selector was
audited as PASS, with no P0 or P1 finding and no production code defect.

Root cause: required test evidence did not independently prove every
authorized same-maximum ambiguity semantic. First, ASOF-SELECT-034 lacked an
explicit same-maximum VALID-versus-invalid quality ambiguity test. Second, the
field-difference parameter cases initialized one record with `sequence_no=100`
while most counterpart records retained `sequence_no=None`, masking the
intended bid, ask, size, raw-file-ID, or quote-condition difference.

Repair: test-only. The repaired parameterized test now creates both records
with the same timestamp and `sequence_no=100`, applies one intended override
to the second record, compares full `model_dump(mode="python")` payloads, and
requires the differing-key set to be exactly the declared field. It then proves
both record orders raise `AsOfSelectionIntegrityError`.

The new explicit test constructs same-source, same-contract, same-timestamp,
same-raw-file, same-size, same-exchange, same-condition, same-sequence-number
quotes that differ only in `ask_px`: one is VALID and one is LOCKED. It verifies
the classifier statuses first, then verifies the selector hard-fails for both
input orders. Quality is therefore not a timestamp-ambiguity tie-break.
