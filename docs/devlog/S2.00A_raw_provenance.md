## 6. Implementation Details

`RawFileManifestRecord` contains exactly the nine persisted fields in
`meta.raw_file_manifest`. It forbids extra fields, is frozen, requires all
fields explicitly, validates a strict lowercase 64-character hexadecimal
SHA-256, requires non-empty caller metadata, and enforces an integer
non-negative row count. The existing `oae.temporal.to_utc` utility rejects
naive timestamps and canonicalizes all aware timestamps to equivalent UTC
instants. The only event-range invariant added is `min_event_ts <=
max_event_ts` when both are present.

`compute_file_sha256` rejects missing and non-regular paths and hashes actual
bytes through binary read-only 1 MiB chunks. `build_raw_file_manifest` has no
digest parameter and preserves the explicit caller-supplied file name and
opaque raw-file identity. `verify_raw_file` recomputes current bytes and raises
the focused `RawDataIntegrityError` on digest mismatch.

`register_raw_file` always verifies bytes before querying for an existing row.
It inserts only through fixed parameterized SQL. Existing rows are compared
across all persisted fields; timestamps are compared as exact DuckDB epoch
microseconds, which is timezone-display independent and avoids adding an
undeclared timezone conversion dependency. An exact record returns as an
idempotent no-op. Any same-ID field conflict raises `RawDataIntegrityError`
without update, delete, overwrite, or duplicate insertion. SHA-256 is not a
uniqueness key.
