## 6. Implementation Details

`select_asof_quote(quotes, decision_ts)` first converts the decision timestamp
with the canonical `to_utc(...)` primitive, so naive decisions fail closed and
equivalent aware timezone representations compare by the same absolute instant.
It returns `None` for an empty stream, then validates every supplied record
(including future records) has exactly the first record's opaque `source` and
`contract_id`. A mismatch raises `AsOfSelectionIntegrityError` before temporal
selection.

The selector scans without sorting or mutating the caller sequence. Each quote
timestamp is converted using `to_utc(...)`; future observations are ignored.
It retains all records at the largest eligible timestamp. One winner is
returned as the existing DTO instance. Multiple winners are accepted only when
their complete `model_dump(mode="python")` payloads are exactly equal; distinct
payloads raise `AsOfSelectionIntegrityError`. No quality classifier, age
threshold, sequence number, input order, quote condition, raw-file ID, or
provider ordering interpretation is used as a tie-break.

Test-scope amendment: YES. S2.04 contained a temporary assertion that
`select_asof_quote(...)` did not yet exist. The Human + ChatGPT S2.05
authorization amendment approved deletion of exactly that one obsolete test
function. No replacement was added to the S2.04 module; selector existence and
semantics are covered by the new S2.05 test module.

## 10. Known Limitations / Risks

1. The selector operates on one exact source-scoped contract stream.
2. It does not construct a multi-contract decision snapshot.
3. Selection intentionally does not apply quote quality or the 2-second
   freshness gate.
4. The selected quote may therefore later classify STALE, LOCKED, CROSSED,
   ZERO_BID, or ZERO_SIZE.
5. Exact duplicate maximum-timestamp records are semantically equivalent for
   selection but are neither persisted nor deduplicated.
6. Distinct maximum-timestamp observations fail closed because no universal
   provider-neutral tie-break is frozen.
7. `sequence_no` is intentionally not interpreted as a universal
   provider-neutral ordering rule.
8. No `source_quote_id` exists yet.
9. No provider-specific event identity semantics exist yet.
10. Missing or all-future streams return `None`; no MISSING status is
    synthesized here.
